\section{Supplementary Note 1: Extended Limitations and Future Work}
%% ============================================================

\paragraph{Top-1 expert purity is modest.} The highest-purity atomic expert we identified (E54, English function-words at layer 12) reaches 80\%, but most ``specialty'' experts land at 15--35\% purity. Our claims about task-specific experts should be understood distributionally rather than as hard assignments.

\paragraph{Single model family.} All results are from Gemma-4-26B-A4B-Instruct. Whether the 96\%/4\% CPT/SFT decomposition generalizes to Mixtral, DeepSeek-MoE, or GPT-class bio models is an open question. The architectures differ in expert count, top-$k$ selection, and router objective.

\paragraph{Remote-homology ceiling.} Our 82.60\% remote-homology accuracy leaves an 18\% error rate. Specialist methods with structural-alignment heads (ESM-2 + TM-Vec, PLMSearch, CATHe) report 65--75\% on differently constructed splits. We hypothesize the remaining gap is a representation-level constraint rather than an SFT-scale constraint; testing requires controlled experiments with more CPT on distant-protein pairs ($\approx$150 GPU-hours, deferred).

\paragraph{No chain-of-thought reasoning.} We briefly attempted to train with \texttt{<THOUGHT>} reasoning blocks for remote homology but abandoned it because synthetic-CoT templates from sequence features were of insufficient quality. Human-expert or strong-teacher-generated CoT data would likely improve remote-homology performance substantially.

\paragraph{Evaluation scale.} BixBench's True/False subset contains only $\approx$200 questions; small absolute differences in the 90--95\% range are within the dataset's noise floor. Richer evaluation pools (HELM-Bio, LM-BIO) would strengthen the claims.

\paragraph{No ablation on \texttt{router.proj} LoRA.} We state that including \texttt{router.proj} in the LoRA target modules is critical to enabling expert re-specialization, based on an informal pilot observation. A controlled ablation --- CPT with and without \texttt{router.proj} LoRA, holding all other hyperparameters fixed --- would quantify this claim.

\paragraph{Future experiments.} (1) Controlled CPT ablation with richer distant-protein corpora. (2) Router.proj ablation. (3) Human-expert CoT for remote homology. (4) Replication on Mixtral-8x7B or DeepSeek-MoE-16B. (5) Downstream wet-lab validation (variant effect prediction on ClinVar). (6) GGUF quantization for single-GPU deployment on RTX 4090.

\section{Supplementary Note 2: OmniGene-4-MM Reproducibility}
%% ============================================================

The multi-modal extension reported in Section~4 of the main text was trained
in three sequential LoRA stages on top of the v5-merged checkpoint, on a
single H20 GPU, in roughly $1.5$ GPU-days total wall-clock. All scripts
referenced below live under \texttt{omnigene5/scripts/} in the project
repository.

\subsection{Pipeline Scripts}

\begin{itemize}
\item \texttt{omnigene5/scripts/01-build\_unified\_jsonl.py} -- Assemble a single multi-modal training corpus from Vis-CheBI20, PubMedVision, HPA10M, ChartQA, BiomedVis, and the v5 SFT pool.
\item \texttt{omnigene5/scripts/02-fix\_image\_paths.py} -- Resolve relative image paths after the corpus assembly step.
\item \texttt{omnigene5/scripts/30-train\_omnigene5\_stage1.py} -- \textbf{Stage 1} (vision warmup, $\sim 10$K steps, LR $5\!\times\!10^{-5}$).
\item \texttt{omnigene5/scripts/50-train\_stage2.py} -- \textbf{Stage 2} (mixed text + vision, $6$K steps, LR $5\!\times\!10^{-6}$).
\item \texttt{omnigene5/scripts/82-train\_stage3v2.py} -- Stage 3 v2 (failed: trainable embedding plateaued at $59\%$ standard homology; kept for reproducibility of the failure mode).
\item \texttt{omnigene5/scripts/83-train\_stage3v3.py} -- \textbf{Stage 3 v3 (final)} (LR $2\!\times\!10^{-5}$, frozen embedding, $3000$ steps; produces the released checkpoint).
\item \texttt{omnigene5/scripts/60-eval\_stage2.py} -- Stage 2 evaluation.
\item \texttt{omnigene5/scripts/91-eval\_stage3v2.py} -- Stage 3 v2 evaluation.
\item \texttt{omnigene5/scripts/92-eval\_stage3v3.py} -- \textbf{Stage 3 v3 evaluation} (BioPAWS standard + remote, Vis-CheBI20 five subtasks, multi-task generation).
\item \texttt{omnigene5/scripts/95-qualitative\_demo\_stage3v3.py} -- Qualitative-showcase generation, 39 examples (vision + homology + multi-task), used for Figure 8.
\item \texttt{omnigene5/scripts/71-router\_analysis\_mm\_extended.py} -- 8-modality router-level analysis on the Stage 2 checkpoint, used for the modality-invariant-transfer evidence in Section~4.
\item \texttt{omnigene5/scripts/98-merge\_mm\_v3.py} -- Merge MM v3 LoRA + extended embedding into the v5-merged base, producing the stand-alone BF16 checkpoint released as \texttt{dnagpt/OmniGene-4-MM-merged}.
\end{itemize}

\subsection{8-Modality Routing Analysis}

The 8-modality routing-divergence numbers reported in the main text are
collected by installing \texttt{forward\_hook}s on all $30$
\texttt{Gemma4TextRouter} modules of the Stage 2 checkpoint, running $50$
prompts per modality across the eight modality categories
(\textit{vision\_molecule}, \textit{vision\_medical}, \textit{vision\_pathology},
\textit{vision\_chart}, \textit{protein\_sequence}, \textit{dna\_sequence},
\textit{structure\_3di}, \textit{natural\_language}), and computing pairwise
Jensen--Shannon divergence per layer over the resulting $30 \times 128$
expert-count matrices, then averaging over layers. The full $8 \times 8$
divergence matrix and per-layer curves are saved to
\texttt{outputs/OmniGene-4-MM-stage2/router\_analysis\_8mod/} when the
analysis script is re-run; key numbers are reproduced below.
